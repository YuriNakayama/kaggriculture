# rulebase/case1 — 小麦ループ

## 仮説

**小麦の単作ループで `starter` を上回れる。**

`starter` は carrot を 1 タイルだけ耕す。carrot は市場の上側形状が
`sqrt / above_target=0.70` で供給過多に弱く（`I0+2T` で $1 まで落ちる）、
かつ 1 タイルでは産出量そのものが小さい。

対して小麦は上側が **`log / above_target=0.20`** で、全商品中もっとも
供給過多に鈍感である（`I0+T` で $25→$20、`I0+2T` でも $19）。
つまり**売り続けても値崩れしない唯一の商品**なので、単作で回す前提なら
小麦が最も素直に稼げるはずだと考えた。

## 実装

NW quadrant のみを使い、farmer と日雇い hand で複数タイルを回す:

1. `BUY_SEED WHEAT` で種を常時 6 個確保（`SEED_BUFFER`）
2. 空きタイルに `PLANT` → **植えた当日に `WATER`**
3. 収穫可能日（`max_yield_day=4`）以降に `HARVEST`
4. 売却は 1 ターン 6 個ずつに分散（`SELL_CHUNK`）
5. hand は毎日 3 人まで雇用（`fib(n)` なので序盤は実質無料）
6. 28 日目以降は在庫を売り切る

各ユニットは足元のタイルに用がなければ**最も近い要作業タイルへ移動**する。
同一タイルへの重複割り当てを避けるため `claimed` で予約管理している。

### 踏んだ罠

- **`consecutive_unwatered` は植付時点で 1 から始まる。** 植えた当日に
  水をやらないとその夜に雑草化する。新規植付に猶予はない
- **同一ターンの `PLANT` 要求が種数を超えると、その作物の `PLANT` が全部
  破棄される**（engine の atomic 検証）。`_unit_action` は消費した種数を
  返し、呼び出し側が予算内に収めている
- ユニット inventory は日末に自動で shed へ流れるので、収穫後に `PLACE` で
  運ぶ必要はない。ただし `SELL` は shed から引くため**売却は翌日以降**

## 結果

`dev/simulate --episodes 20 --swap-sides --strict`（120 エピソード）:

| 相手 | W/L/T | 勝率 | 平均所持金 | 平均差分 |
|---|---|---|---|---|
| starter | 40/0/0 | 100.0% | 9,033 | +5,546 |
| random | 40/0/0 | 100.0% | 9,381 | +9,377 |
| pass | 40/0/0 | 100.0% | 9,896 | +6,896 |

health: crashes 0 / timeouts 0 / slow 0 / invalid actions 0
（max turn 0.038s / limit 1.000s）

**仮説は支持された。** 平均所持金 9,033 に対し、`starter` 自身が `pass` 相手に
稼ぐのは 3,484（実測）なので約 2.6 倍。

### 初版からの改善

初版はユニットが移動せず 1 タイルしか耕していなかった。シミュレータは
勝率 66.7% / 平均 3,557 と報告し、移動ロジック追加後に **100% / 9,033** に
なった。1 タイル運用では `starter` と大差ないことが逆に確認できた形で、
**効いているのは作物選択より並列耕作**である可能性が高い。

## 次の case への申し送り

- **土地購入が未検証。** NW のみで 9,000 程度。NE が $1,000 なら回収可能か
- **hand の上限 3 人は根拠が弱い。** `fib(n)` は 1,1,2,3,5,8 なので 5〜6 人まで
  伸ばせる可能性がある
- **単作である必要はない。** 小麦を安定収入の土台に据えつつ、melon や
  strawberry を「値崩れしない量だけ」売る混作が本命かもしれない
- 家畜・肥料は完全に未着手
