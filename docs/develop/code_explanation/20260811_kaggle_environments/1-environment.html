00 このゲームと用語

以降で使う言葉を先に固定する。すべてこの実装の中で定義されたもの。

2 人のプレイヤーがそれぞれ 10×10 の農場を経営し、 30 日 × 1 日 24 ターン = 720 ターンを戦う。 作物を植え、水をやり、収穫し、共有の市場に売る。 終了時点の所持金が多い方が勝ちで、売れ残った在庫は 0 点として扱われる。

用語集

ターン step
判断の 1 単位。両プレイヤーが同時に 1 手ずつ出し、まとめて処理される。全 720 回。
象限 quadrant
農場を 4 分割した 5×5 の区画。北西だけ無料。残りは $1,000 → $2,000 → $4,000 の順でしか買えない。
倉庫 shed
農場の中央にある保管庫。市場に売れるのは倉庫の中身だけ。非種アイテムを合計 100 個まで。
手持ち inventory
農夫や雇い人が手に持っている分。収穫物はまずここに入る。1 日の終わりに倉庫へ移され、空になる。
種 seeds
倉庫とも手持ちとも別の独立した勘定。市場で買い、植えるときだけ減る。売ることはできない。
農夫 farmer
常に 1 人いる操作対象。盤上を 1 ターンに 1 マス動き、立っているマスに対して作業する。
雇い人 farm hand
その日だけ雇える追加の作業者。同じ日の n 人目の費用はフィボナッチ数列（1,1,2,3,5,8…）。日が変わると全員消える。
雑草 weed
何も育たない状態のマス。放置した作物・逃げた動物・自然発生（空きマスに 1 日 0.5%）で生じる。除去には 1 手かかる。
継続作物 ongoing
収穫してもマスに残り、繰り返し実る作物。トマトと苺の 2 つだけ。他の 3 つは 1 回収穫すると消える。
市場在庫 market inventory
その商品が世界にどれだけ出回っているかを表す数。両プレイヤーで共有し、価格はこの数だけで決まる。自分の倉庫の中身とは別物 —— 詳しくは 05 節。
均衡在庫 I0
全商品で 10,000。市場在庫がちょうどこの値のとき、価格は商品ごとの基準価格に一致する。ここを境に値動きの向きが変わる。
基準価格 base
市場在庫が均衡在庫のときの値段。商品ごとに固定（小麦 $25、メロン $250 など）。
町 town
市場在庫を定期的に減らす需要側。3 日ごとに店が 1 つ増え、店は減らないので需要は増える一方。
観測 observation
毎ターン各プレイヤーに渡される情報。相手の盤面は見えるが、相手の倉庫・種・所持アイテムは見えない。

エージェントが書くもの

参加者が実装するのは agent(観測) → 行動 という関数 1 つだけ。 以下は環境に同梱されている手本（starter_agent、1041 行）の骨格で、 人参を植えて水をやり収穫して売るという最小の循環になっている。 

def agent(obs):
    farm    = obs["farms"][obs["player"]]   # 自分の盤面（相手の分も入っている）
    fx, fy  = farm["farmer"]                # 農夫のいるマス
    tile    = farm["tiles"][fy][fx]         # そのマスの中身
    seeds   = obs["private"]["seeds"]       # 種（自分だけ見える）
    shed    = obs["private"]["shed"]        # 倉庫（自分だけ見える）

    # --- 市場注文: 最大 10 件、順番が意味を持つ ---
    market = []
    if shed.get("CARROT", 0) > 0:
        market.append(["SELL", "CARROT", shed["CARROT"]])   # 倉庫の分だけ売れる
    if seeds.get("CARROT", 0) == 0:
        market.append(["BUY_SEED", "CARROT", 1])

    # --- 農夫の 1 手: 立っているマスの状態で分岐 ---
    farmer = ["PASS"]
    if tile is None:                        # 空きマス → 植える
        farmer = ["PLANT", "CARROT"]
    elif tile["kind"] == "PLANT":
        age = obs["day"] - tile["planted_day"]
        if age >= 3:                        # 育ちきった → 収穫
            farmer = ["HARVEST"]
        elif not tile["watered_today"]:      # まだ → 水やり
            farmer = ["WATER"]

    return {"farmer": farmer, "hands": [], "market": market}
失敗が例外として現れない

間違った命令名、範囲外の座標、11 件目の市場注文は エラーにならず、黙って捨てられる。 そのターンが無駄になるだけで、実行は続く。 つまり不具合はクラッシュではなく点数の低さとしてのみ現れる。

04 1 ターンの処理順

両プレイヤーの行動を受け取ってから、次のターンに移るまで。

市場の値動き

価格の仕組みは ③ 市場と生産 で扱う。ここでは 売却 1 個ごとに価格が引き直されるという点だけ押さえておけばよい。

05 実装から見える 3 つの落とし穴

コードを読まないと気づけない挙動。

落とし穴 1
盤面が乱数を動かす空きマスの数で店が変わる
落とし穴 2
ターン番号の所有権フレームワーク側にある
落とし穴 3
失敗が無音点数の低さとしてのみ現れる
  • ターン番号を進めるのはフレームワーク側 —— day と hour はターン番号からの計算値なので、 ルール本体だけを自前で回すとターン番号が止まったままになる。 すると 1 日の終わりの処理が一度も走らないまま、 それらしい点数で試合が完走してしまう。例外は出ない。
  • 無効な行動は例外にならない —— 間違った命令名も、範囲外の座標も、11 件目の市場注文も、黙って捨てられる。 不具合はクラッシュではなく点数の低さとしてのみ現れるため、 通常なら例外が担う「間違いの通知」を、行動を組み立てる側の検査が肩代わりする必要がある。
  • 売却は自分で価格を押し下げる —— 注文 1 個ごとに価格が計算し直されるため、まとめ売りは進むほど手取りが減る。 相手も同じ在庫に売り込むので、いつ売るかは相手の在庫の推定と不可分になる。 そしてその在庫は観測に含まれない。
