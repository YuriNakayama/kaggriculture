00 在庫と価格の基礎

2 種類の在庫を区別し、価格計算のロジックを追う。

2 種類の「在庫」を区別する

この環境には名前が似た在庫が 2 つあり、混同すると価格の動きが読めなくなる。 持ち物としての在庫と、値段を決める世界全体の在庫は別物である。

価格はどう決まるか

価格は市場在庫だけの関数である。基準となるのが 10,000 個という数値で、 全商品で共通のこの値を本稿では均衡在庫と呼ぶ （コード上の名前は I0）。 市場在庫がちょうど均衡在庫に等しいとき、価格は商品ごとに決められた基準価格に一致する。

価格計算のロジック

価格関数（ルール本体 179 行）を、実際の定数を入れた形で書き下すと以下になる。 入力は市場在庫だけで、日付・所持金・相手の状態は一切関与しない。 

# ── 使われる 5 つの曲線 ───────────────────────────────
def 曲線(種類, x):
    x = max(0, x)
    linear → x           # そのまま
    sq     → x * x       # 2 乗。急激
    sqrt   → √x          # 平方根。緩やか
    log    → ln(1 + x)   # 対数。最も緩やか。x=0 で 0 になるよう 1 を足す
    log10  → log₁₀(1 + x)

# ── 増幅率は「T 個売ったら target 割動く」から逆算する ──────
増幅率 = target × 基準価格 / 曲線(種類, T)
#        ↑ここが設計の要。増幅率を直接決めるのではなく、
#          「1 区画分（T 個）を売り切ったときの下落幅」を指定している

# ── 価格 ───────────────────────────────────────
def 価格(市場在庫):
    if 市場在庫 < 10000:                       # ── 品薄側 ──
        差 = 10000 - 市場在庫
        p = 基準価格 + 増幅率_下 × 曲線(種類_下, 差)
    else:                                     # ── 供給過多側 ──
        差 = 市場在庫 - 10000
        p = 基準価格 - 増幅率_上 × 曲線(種類_上, 差)

    return max(1, round(p))                   # 下限 $1、整数に丸める
T が意味を決めている

T は「1 区画（5×5）を 24 日間フル稼働させたときの生産量」で、 商品ごとに違う（苺 100、小麦 400 など）。 target は「その T 個を売ったら基準価格の何割ぶん動くか」。 たとえば苺は above_target = 1.60 なので、 100 個売ると基準価格の 1.6 倍ぶん下がる —— 基準が $120 なので $192 下がることになり、当然 $1 の床に突き当たる。 「1 区画で作れる量」が価格設計の物差しになっているのがこの環境の核心である。

T 個を売り切ったときの総収入を見ると、 メロンは 300 個で $26,627 と全商品中の最高である。定価比では 36% しか回収できていないのに、 それでも小麦の $8,313 の 3 倍を超える。 つまり「崩れやすい ＝ 弱い」ではない —— 単価が高い商品は、 値崩れしてもなお総額で上回りうる。

逆に苺は定価 $120 と高めでも T が 100 と小さく、総収入 $3,847 で全商品中の最低になる。 判断材料は単価でも崩れやすさでもなく、単価 × 生産量 × 売り切れる割合の積である。

9 商品の下落曲線を重ねる

横軸は均衡在庫から何個売ったか、縦軸は基準価格に対する割合。 単価が違う商品を比べるため縦軸を正規化してある（上端が定価、下端が 0）。 すべて価格関数で実際に計算した値である。

メロンの形が特殊

2 乗曲線は差が小さいうちは効かない。メロンは +50 個までは定価の 9 割を保つのに、+158 個で床に着く。 つまり「安全な量」がはっきり存在し、その先で崖になるタイプで、 線形の苺・牛乳（最初から一定の傾きで下がる）とは売り方の考え方が変わる。

実際の金額で見る — 価格帯ごとの比較

上のグラフは正規化してあるため、「どちらが高く売れるか」は読み取れない。 そこで縦軸を実際のドル額にしたものを、価格帯の近い商品どうしで 3 組に分けて示す。 縦軸・横軸ともに正規化していないので、線の高さがそのまま手取り単価になる。

唯一の例外がメロンで、羊毛に対してどの数量でも優位が崩れない。 同じ 2 乗曲線でも、定価が高くかつ T が大きい（300 対 105）ぶんだけ余裕がある。

02 売却のタイミング

いつ価格が引き直され、どう売れば手取りが増えるか。

いつ価格が引き直されるか

価格は売却 1 個ごとに再計算される。 ここでの「1 個」はターンでも注文でもなく、約定 1 単位である。 以下はその処理順を実際に追ったもの。

価格が引き直される瞬間
タイミング頻度何が起きるか
約定 1 個ごと 売買 1 単位ごと 在庫が動き、次の 1 個は新しい価格で約定する
注文 1 件の完了後 市場注文ごと obs["market"]["prices"] が書き換わる
町の消費の直後 4 ターン / 24 ターンごと 在庫が減り、価格が戻る

メロン 50 個を売る際、分け方を変えて手取りを比較した結果である。 在庫はすべて均衡（10,000）から始めている。

同一ターン内でいくら注文を刻んでも手取りは 1 円も変わらない。 価格が回復するのは町が在庫を吸ったときだけで、 それはターンの経過によってしか起きないからである。

逆に言えば、売却ペースを町の消費速度以下に抑えれば価格は下がらない。 町の需要はおおむね 1 商品あたり 1 日 7 個前後（町全体で 1 個 + 店 1 軒につき 6 個）なので、 これが「値を崩さずに売れる速度」の目安になる。 ただし季節は 30 日しかなく、倉庫は 100 個しか持てない。 売り切る速度と値を守る速度が両立しないところに、この競技の中心的な葛藤がある。

相手の売却がどれだけ効くか

メロン 50 個を売るとき、自分だけなら $12,098、相手も同時に 50 個売ると $10,883。 約 10% の目減りである。相手の在庫は観測できないので、 この差は事前には計算できない。 崩れやすい商品ほどこの不確実性が大きくなる。

植えた瞬間、そのマスの「連続未水やり日数」は 0 ではなく 1 から始まる （_new_plant 209 行）。 つまり植えた日のうちに水をやらないと、その日の終わりに 2 に達して雑草になる。 実測でも、翌日に水をやる方針では全作物が 1 日で全滅した。 植える手と水やりの手は同じ日に確保しなければならない。

水やりは毎日必要か

枯らさないだけなら 1 日おきで足りる。 枯れる条件は「連続 2 日の未水やり」なので、1 日空ける程度では雑草にならない。 ただし収穫量は作物によって減る。以下は実測値である。

継続作物は水やりで増えない

水やりが収穫量を増やすのは1 回で消える作物（小麦・人参・メロン）だけである （_apply_unit_action 425 行の if not crop_data["ongoing"]）。 トマトと苺は日次生産で自動的に実るので、水やりは「枯らさないための維持作業」でしかない。 したがって継続作物では、1 日おきに切り替えると手数が半分になり、収量は変わらない。

2 日おきは成立しない

実測すると、2 日おき（3 日に 1 回）ではメロンが 2 日目で雑草化した。 未水やりが 2 日連続した時点で判定に引っかかるためで、 「1 日空ける」は許されるが「2 日空ける」は許されない。 安全側の運用は隔日までである。

なお植えた当日だけは例外で、必ず水をやる必要がある（下の警告を参照）。 「初日 + 以降 1 日おき」が最小の手数になる。 

# 水やりの判定ロジック（_daily_refresh_plants 764 行）

1 日の終わりに、各作物のマスについて:

    if 今日 水をやった:
        連続未水やり = 0
    else:
        連続未水やり += 1

    水やり済みフラグ = False          # 翌日また水をやれる状態に戻す

    if 連続未水やり >= 2:
        このマスは雑草になる           # ここで作物が失われる

# つまり「1 日おき」なら 連続未水やり は 0 → 1 → 0 → 1 … と振動し
# 2 に到達しないため枯れない

作物の作業手順

# 1 マスあたりの手順（すべて、そのマスの上に立って行う）

  ┌─ 事前 ──────────────────────────────────
  │  市場で  ["BUY_SEED", 作物名, 個数]        # 倉庫を通らない
  │
  ├─ 0 日目 ────────────────────────────────
  │  空きマスへ移動して  ["PLANT", 作物名]      # 種を 1 消費

  │

  │  （任意）["FERTILIZE"]                     # 手持ちの肥料 1 個、3 日間 効果 2 倍

動物まわりの補足

上のカードで示した手順を、命令の形でまとめておく。 買っただけでは生産が始まらず、倉庫から取り出して小屋に置く必要がある点が 作物との最大の違いになる。 

# 動物 1 匹を稼働させるまで（4 手 + 移動）

  1. 空きマスで  ["BUILD_COOP"]  または  ["BUILD_PASTURE"]   # 費用は無料
  2. 市場で      ["BUY_ANIMAL", 動物名, 1]                    # 倉庫に入る
  3. 倉庫の脇で  ["PICKUP", 動物名, 1]                        # 手持ちへ
  4. 小屋の上で  ["PLACE", 動物名]                            # ここで初めて稼働

# 稼働後、毎日必要な作業

  ["FEED"]                 # 手持ちの小麦を 1 個消費。2 日忘れると逃げる
  ["CARE"]                 # 任意。餌もやった日なら次の生産が +1
  ["HARVEST"]              # 溜まった産物を手持ちへ
  ["COLLECT_FERTILIZER"]   # 任意。1 日 1 個たまる
餌代を差し引くと見え方が変わる

どの動物も1 日 1 個の小麦を食べる。30 日ぶんを均衡価格 $25 で買えば $750 で、 これは初期費用と同じ桁になる。牛の 30 日の売上 $1,920 に対し、 初期 $400 + 餌 $750 = $1,150 が原価という計算になる。

さらに、羊毛と牛乳は60〜76 個で $1 に落ちる崩れやすい商品である。 羊 1 匹の 30 日産出は 9 個なので単体なら問題ないが、 複数飼えばすぐ床に近づく。 一方ガチョウの卵は崩れない対数曲線なので、数を増やしても単価が保てる。

世話ボーナスの仕組み

["CARE"] はその場では何も起きない。 餌もやった日に限り内部カウンタが 1 増え、 次の生産日にまとめて上乗せされる（pending_care_bonus）。 牛や羊のように生産間隔が 2〜3 日ある動物では、 その間の世話が積み上がって次の産出に反映される仕組みになっている。

肥料 — 唯一の副産物

肥料の 2 つの入手経路
経路手順コスト備考
動物から回収 ["COLLECT_FERTILIZER"] 1 手のみ 動物 1 匹につき 1 日 1 個。「あり / なし」の 2 状態で管理されるため蓄積せず、 回収しなかった日のぶんは失われる
市場で購入 ["BUY_PRODUCT", "FERTILIZER", n] $100 前後 小麦と並んで、買える 2 商品のうちの 1 つ

肥料は売ってもよいし、畑に使ってもよい。 ["FERTILIZE"] で施すと 3 日間、水やりと日次生産の効果が 2 倍になる。 値崩れしにくい線形曲線（493 個で床）なので、 売却先としても安定している。

市場在庫を戻す力 — 町の需要

売却で増えた市場在庫を減らすのは町だけである。 町は 2 系統の需要を持ち、どちらも市場在庫を直接減らす。 在庫が減れば価格は均衡へ、さらには均衡未満へと戻っていく。

需要周期買うもの増え方
町全体 24 ターン（1 日）ごと 肥料以外の全商品を 1 個ずつ 一定。増えない
個々の店 4 ターンごと その店の扱う商品を 1 個ずつ（1 品目のみの店は 2 個） 3 日ごとに 1 店ずつ増え、減らない（上限 8 店）
需要は後半ほど厚くなる

店は解禁されるだけで閉店しないため、季節が進むほど市場在庫が吸われる速度が上がる。 同じ 100 個でも、序盤に売れば値を潰し、終盤なら町が吸ってくれる分だけ有利になりうる。 ただしどの店が解禁されるかは乱数で決まり、盤面の状態にも左右される（① 落とし穴）。 需要の中身を先読みして作付けを決める、という戦略は成立しにくい。

売り時の問題が最後に残る

終了時に売れ残った在庫は 0 点である。 一方でまとめ売りは価格を潰す。しかも相手も同じ市場在庫に売り込んでおり、 その手持ちは観測に含まれない。 結果として、「いつ・どれだけ売るか」は相手の在庫の推定と切り離せない問題になる。 季節の終わりは生産の問題ではなく、売り抜けの問題として立ち現れる。
