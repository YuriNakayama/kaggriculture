00 観測 — 受け取る情報

obs に何が入っているか。全キーを実測値で展開する。

受け取る観測の全体

obs は 9 個のキーを持つ辞書型である。 以下は実際に環境を動かして取得した中身を、入れ子をすべて展開したもの。 値は開始直後（0 日目 0 ターン目）の実測値。 区切りコメントに共有か自分専用かを明記してある。 

obs = {
  # ───── 基本情報（すべて整数）─────────────────────────────
  "player":   0,        # 自分がどちらか。0 か 1
  "day":      0,        # 何日目か。0〜29
  "hour":     0,        # その日の何ターン目か。0〜23
  "step":     0,        # 通算ターン数。プレイヤー 1 には存在しない
  "remainingOverageTime": 60,   # 持ち時間の残り（秒）

  # ───── farms：盤面。自分と相手の両方が入る ──────────────
  "farms": [
    {                                    # farms[0] = プレイヤー 0 の農場
      "money":              3000.0,      # 所持金。これが最終得点
      "tiles":              [[…], …],    # 10×10。tiles[y][x] の順
      "farmer":             [4, 4],      # 農夫の座標。[x, y] の順
      "hands":              [],          # 雇い人の座標を雇った順に
      "unlocked_quadrants": ["NW"],      # 購入済み区画
      "hires_today":        0,           # 今日すでに雇った人数
    },
    { … },                               # farms[1] = 相手の農場。同じ 6 キーが全部見える
  ],

  # ───── private：自分の分だけ。相手のものは入らない ─────────
  "private": {
    "shed":   {"WHEAT": 0, "CARROT": 0, … , "GOOSE": 0, …},  # 倉庫。12 キー固定
    "seeds":  {"WHEAT": 0, "CARROT": 0, … , "MELON": 0},     # 種。5 キー固定
    "inventories": [ {} ],   # 手持ち。先頭が農夫、以降が雇い人
  },

  # ───── market：市場。共有 ───────────────────────────
  "market": {
    "inventory": {"WHEAT": 10000, "CARROT": 10000, … },  # 9 商品の市場在庫
    "prices":    {"WHEAT": 25,    "CARROT": 35,    … },  # 9 商品の現在価格
  },

  # ───── town：町。共有。キーは 1 つだけ ──────────────────
  "town": {
    "unlocked_shops": [],    # 解禁済みの店名。同じ店が重複して並びうる
  },
}
4 つの塊の性格 — どれが誰に見えるか
キー中身個数 相手の分主な用途
farms 農場の盤面と所持金 2 人分 見える 自分の作業計画。相手の生産量の推定
private 倉庫・種・手持ち 自分のみ 見えない 何を売れるか、何を植えられるかの判断
market 市場在庫と価格 共通 1 つ 共有 売り時の判断（→ ③）
town 解禁済みの店 共通 1 つ 共有 今後の需要の見積もり
step はプレイヤー 1 には届かない

実際に確認すると obs のキーはプレイヤー 0 が 9 個、 プレイヤー 1 は 8 個で、step だけが欠けている。 通算ターン数が要るなら day * 24 + hour で計算するか、 obs.get("step") と既定値つきで読むこと。 先手では動くのに後手で落ちるコードは、たいていこれが原因になる。

座標の順序が場所によって逆になる

盤面は tiles[y][x]（縦が先）だが、農夫と雇い人の座標は [x, y]（横が先）で入っている。 足元のマスを読むには fx, fy = farm["farmer"] のあと farm["tiles"][fy][fx] と添字を入れ替える。 間違えても例外にならず、別のマスを見に行くだけなので気づきにくい。

tiles — マス 1 つの中身

tiles[y][x] は次の 7 通りのいずれか。 相手のマスについても同じ情報がすべて見える。

マスが取りうる 7 通り

None空き 植える / 小屋・牧場を建てる
"LOCKED"未購入の区画 通過のみ。作業は全て無効
{"kind": "PLANT", …}作物が育っている 水やり / 収穫 / 施肥 / 除去
{"kind": "WEED"}雑草 除去のみ
{"kind": "COOP"}鶏小屋（動物なし） ガチョウを置く / 除去

}

01 在庫の制約

種・手持ち・倉庫で制約が違う。溢れる問題が起きるのは倉庫だけ。

在庫の制約と、物の流れ

在庫は 3 か所（種・手持ち・倉庫）に分かれ、 それぞれ制約が違う。 以下はすべて実際に環境を動かして確認した挙動である。

3 か所の制約の比較
種 seeds手持ち inventories倉庫 shed
容量 無制限 無制限 合計 100 個
入るもの 5 作物の種のみ 9 商品 + 3 動物 9 商品 + 3 動物
動物も枠を 1 つ消費する
日をまたぐと そのまま残る 倉庫へ流され空になる そのまま残る
持ち主 プレイヤーに 1 つ 作業者ごとに 1 つ
農夫 + 雇い人の人数分		 プレイヤーに 1 つ
売却 できない できない ここからのみ
置き場所の制約 なし なし。作業者が持ち歩く 出し入れは中央 4 タイルの上でのみ
制約があるのは倉庫だけ

種と手持ちには上限がない。実際、満杯の倉庫から 繰り返し取り出して手持ちを 100 個まで膨らませることができた。 つまり「入り切らない」問題が起きるのは倉庫だけで、 倉庫の 100 枠をどう使うかが在庫管理のほぼ全てになる。 動物も 1 匹につき 1 枠を占めるので、購入したまま設置し忘れると売り物の枠を圧迫する。

倉庫が満杯のときに何が起きるか

入れ方によって挙動が違う。 購入は「入らなければ丸ごと失敗」、手持ちからの移動は「入る分だけ入れて残りは消滅」する。 以下は実測結果である。

手持ちに複数の品目があると、先に入っていた品目から順に倉庫へ詰められ、 枠が尽きた時点で残りは丸ごと消える。品目の価値は考慮されない。
実測 — 空き 3 の倉庫に「メロン 5 個 + 人参 5 個」を入れると メロン 3 個だけが残り、人参は 5 個とも消えた。 順番を逆に持つと、今度は人参 3 個が残ってメロンが全部消えた。

つまり高価なものを先に収穫しておけば生き残るという、 直感に乏しい優先順位が働く。安全側に倒すなら、 日が変わる前に自分で DROP して空きを確認するほうが確実である。 

# 倉庫まわりで踏みやすい 3 つの前提

# 1. 空き枠の計算 — 動物も枠を消費する
空き = 100 - sum(obs["private"]["shed"].values())
#      ↑ WHEAT〜FERTILIZER の 9 商品に加え GOOSE/COW/SHEEP も合算される

# 2. 手持ちは 0 個の品目がキーごと消える
carried = obs["private"]["inventories"][0]
n = carried.get("MELON", 0)      # carried["MELON"] は KeyError になりうる

# 3. 売れるのは倉庫の分だけ。収穫直後は倉庫に入っていない
売れる数 = obs["private"]["shed"].get("MELON", 0)
#          ↑ 手持ちの分を足してはいけない。SELL は倉庫しか見ない
在庫管理として何を決めることになるか

倉庫の 100 枠は「売れるまでの待合室」であり、 枠が埋まっていると収穫物が捨てられ、購入も通らなくなる。 一方で価格を潰さずに売るには少しずつ売るしかない（③ 売却のタイミング）ので、 売り急ぐと安く、貯めると溢れるという板挟みが生じる。 これが「作った分だけ儲かる」を成立させない 2 つ目の理由になっている。

obs["market"] と obs["town"]
キー形意味

9 商品		 市場在庫。価格の唯一の入力（→ ③）

観測に含まれないもの

相手の private（倉庫・種・手持ち）は一切入らない。 相手が何をどれだけ抱えているかは、盤面と市場在庫の推移から推定するしかない。 また乱数の種、次に解禁される店、天候にあたる要素も観測されない。

02 行動 — 返す内容

3 つのキーと、使える 24 の命令。

返すべき行動の全体

返り値は 3 キーの辞書型で固定である。キーが欠けていても例外にはならず、 その部分が「何もしない」扱いになる。 

return {
  "farmer": [命令, *引数],          # 必ず 1 つ。リストが 1 段であることに注意
  "hands":  [[命令, *引数], …],     # 雇い人の人数とちょうど同じ数。順番は雇った順
  "market": [[命令, *引数], …],     # 最大 10 件。11 件目以降は黙って捨てられる
}

# 何もしないとき（例外を捕まえたときの安全な既定値）
{"farmer": ["PASS"], "hands": [], "market": []}

農夫・雇い人が使える 18 の命令

"farmer" と "hands" には同じ命令が使える。 立っているマスに対して作用するのが基本で、 条件を満たさなければ黙って何も起きない。

市場注文の 6 命令

obs["market"] に並べる命令。1 ターンに合計 10 件まで
命令書き方効果無効になる条件
SELL["SELL", 品目, 個数] 倉庫から売る。1 個ずつ約定し、そのたび価格が下がる 倉庫にない。足りない分は途中で打ち切られる
BUY_SEED["BUY_SEED", 作物名, 個数] 種を買う。値段は固定で市場在庫の影響を受けない 所持金不足
BUY_PRODUCT["BUY_PRODUCT", 品目, 個数] 商品を買って倉庫へ。小麦と肥料しか買えない 所持金不足 / 倉庫が満杯
BUY_ANIMAL["BUY_ANIMAL", 動物名, 個数] 動物を買って倉庫へ。設置は別途 PLACE で行う 所持金不足 / 倉庫が満杯
HIRE["HIRE"] 雇い人を 1 人。個数は指定できず、1 件で 1 人 所持金不足
BUY_LAND["BUY_LAND"] 次の区画を購入。買う場所は選べず順番が決まっている 所持金不足 / 全区画を購入済み
品目名の一覧

作物（PLANT と BUY_SEED で使う）— WHEAT CARROT TOMATO STRAWBERRY MELON
動物（BUY_ANIMAL と PLACE で使う）— GOOSE COW SHEEP
商品（SELL で使う。作物 5 種に加えて）— EGG MILK WOOL FERTILIZER

同じターンに雇って働かせることはできない

雇用は市場注文として処理され、その処理は農夫・雇い人の行動より後に走る。 実際に試すと、["HIRE"] と同時に "hands" へ ["EAST"] を渡しても雇い人は倉庫脇に立ったままで、動くのは次のターンだった。 雇った当日は 1 手も働かないため、雇用費用は 「残りターン数ぶんの労働」に対して支払っていることになる。 盤上に出たかどうかは obs["farms"][自分]["hands"] の長さで確認できる。
