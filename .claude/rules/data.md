# Data Layout Rules

`data/` is the data layer of the repository. **Actual contents are git-untracked and managed by DVC + S3.** Only `*.dvc` / `*.md` / `.gitkeep` / `.gitignore` files are tracked by git.

## Top-level layout (4 fixed layers)

Do **not** create any directory directly under `data/` other than the four layers below. When adding a new use case, classify it into one of these four layers and create a subdirectory under it.

```
data/
├── lake/        Raw data (collected as-is, no processing)
├── processed/   Pre-processed data (intermediate artifacts)
├── mart/        Curated data for training/evaluation (aggregated tables, etc.)
└── output/      Final pipeline artifacts
```

| Layer | Nature | Examples |
|---|---|---|
| `lake/` | Immutable, original. Re-acquisition required if lost | `lake/kaggle_episodes/replays/` (leaderboard replay JSON) / `lake/selfplay/replays/` |
| `processed/` | Intermediate data derived from lake | Parsed replay → per-turn parquet |
| `mart/` | Curated data read directly during training/evaluation | `mart/imitation/case1/{train,val}.parquet` |
| `output/` | Pipeline execution results, regenerable | `output/models/` (trained weights) / `output/submit/` (submission tar.gz + history) / `output/scrape/` (scrape run logs) / `output/experiment/` (experiment JSON / plots) |

## How to choose a layer

- **Need re-acquisition if lost → `lake/`**
- **Reproducible by re-running code → `output/`**
- **Between lake and output, consumed by other pipelines → `processed/` or `mart/`**
- When in doubt: **inputs default to `lake/`, outputs default to `output/`**

## Subdirectory naming

- Directly under each layer: split by **use-case domain** (`kaggle_episodes/`, `selfplay/`, `imitation/`, `rulebase/`, `models/`, `submit/`, `scrape/`, `experiment/`)
- Below the domain: split by **case name** (`imitation/case1/`, `submit/rulebase/case3/`)

## DVC management

- Track each directory under lake / mart / output with `dvc add` at the **directory** level. Commit only the generated `*.dvc` files to git
- S3 remote is named `s3`; the bucket is created by Terraform (`infra/module/application/dvc_remote`) and wired up per-machine via `dev/dvc setup`
- Fetch real contents with `dev/dvc pull`
- Kaggle replay/log scraping is automated — see `.github/workflows/scrape-kaggle.yml` and `.claude/rules/command.md`

## .gitignore behavior

`.gitignore` ignores everything under `/data/**` **except**:

- `*.dvc` (DVC tracking files)
- `*.md` (README and similar)
- `.gitignore` (including those auto-generated by DVC)
- `.gitkeep` (placeholder for empty directories)

Real data (parquet, json, json.gz, tar.gz, png, model weights) must never be committed. **This repository is public** — treat an accidental data commit as a rewrite-history incident, not a follow-up cleanup.

## Prohibitions

- **No directories directly under `data/` other than lake / processed / mart / output**
- Never commit real data to git (manage via `.dvc` files)
- Use repository-root-relative paths (`data/...`), not hardcoded absolute paths
